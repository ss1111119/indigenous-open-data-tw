# 763 筆開放資料集品質分級

以實際打端點取回的內容判定，不採信 metadata 的格式欄。
探測樣本：每個資料集最多 2 個代表性資源（頭尾各一）。
失敗項目一律重試過，以區分暫時性故障與真正失效。

| 分級 | 含義 |
|---|---|
| 真資料 | 端點回可解析內容且有記錄，可直接使用 |
| 二進位 | 回傳 PDF／ZIP／XLS 本體，需另行解析才知內容 |
| 連結殼 | 有記錄，但欄位是檔案連結，真正的數字在附件裡 |
| 空資料 | 可解析但 0 筆記錄 |
| HTML殼 | 宣稱資料格式卻回 HTML（SPA、錯誤頁或登入頁） |
| 網址無效 | **ODPortal 索引的網址本身壞掉**（含字面 `undefined` 或參數為空）。資料本身可能是好的，問題在索引，不是提供機關 |
| 失效 | 網址正常但連線失敗或伺服器錯誤，重試後仍失敗 |
| 無資源 | 清單上沒有任何資源網址 |

## 重複項——已去重（2026-08-13）

**160 筆資料集與其他資料集共用資源網址**（佔 21.0%）。

⚠️ 本節原先寫「共用**完全相同**的資源網址」，2026-08-13 實測後修正：**只有 68 筆兩側資源完全相同**，另 92 筆是部分重疊。這個差別很重要——見下方。

實測確認這 160 筆是**同一份資料上架在中央的政府開放資料平臺與地方入口網**，名稱與資源 `rid` 相同，組合以臺中市為絕大多數，桃園、臺北零星。**不是各轄區的拼圖碎片**，所以該合併。

### 去重結果

**`catalog/odportal-deduped.csv`：683 筆**（763 筆中，80 個成對群各併為一筆）。

連通分量分群得 603 個單筆群 ＋ 80 個雙筆群，無三筆以上的群。

### ⚠️ 為何不能「留一筆、刪一筆」

| 情況 | 筆數 | 「留一筆」的後果 |
|---|---:|---|
| 兩側資源完全相同 | 68 | 安全 |
| 少的一側是多的一側的子集 | 46 | 留資源多的那筆即無損 |
| **兩側各有對方沒有的資源** | **46** | **無論留哪筆都會掉資料** |

**且平台優先序無效**——中央較全與地方較全各佔約一半，沒有一致方向性。落差最大達 10 倍：

```
10730-09-01-2 臺中市原住民權益及福利宣導統計
    政府開放資料平臺 183 個資源  vs  臺中市政府 18 個
```

**故規則為取資源聯集。** 實測驗證：去重前後的資源網址聯集皆為 **4,654 個**，不多不少。

### ⚠️ 23 筆的分級欄位未涵蓋新增資源

聚集後有 23 筆的資源數超過任一成員原本的數量。這些列的 `最大記錄數`、`檔案類欄位`、`實際型態` 仍是舊樣本的結果，**未涵蓋合併後新增的資源**，以 `分級未涵蓋新增資源` 欄標示為真。

不重新探測是刻意的：代價是又一波對政府主機的請求，且會使分級結果與本報告的既有數字不一致。分級本身也只取每個資料集最多 2 個代表性資源為樣本，本來就不是逐一資源全驗。
