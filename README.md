# indigenous-open-data-tw

台灣原住民族公開統計的整理專案。

## 這是什麼

**把散在各機關、各年度、各種格式的原住民族公開統計，整理成可直接讀進 pandas 的長表。**

不是蒐集資料，不是原生調查，不代表任何族群或機構發言。只做「政府已公開的加總統計」的再整理。

## 為什麼做

2026-08-12 的盤點結果（見 `docs/來源盤點.md`）：

- ODPortal 上名稱含原住民關鍵字的資料集 **763 筆**
- SEGIS 另有 **120 筆**，空間解析度最細，且「原住民」是正式的統計小類
- 教育部有 21 學年度、12 年 Excel

那 763 筆已實際打端點分級（2026-08-12，1,272 個端點）：**真資料 600 筆（78.6%）**，另有 160 筆（21.0%）與其他資料集共用完全相同的資源網址，即同一份資料重複上架。

**資料不缺，缺的是整合。** 可用性不是瓶頸——真資料有 600 筆；瓶頸在它們拼不起來。絕大多數是單一縣市、單一年度、單一局處的小檔案。想回答「原住民失業率十年怎麼變」，得自己拼幾十個檔。沒有任何一個地方提供跨年度可比、機器可讀的長表。

唯一做過整合嘗試的臺灣原住民族資訊資源網（TIPP）已經失效。

## 範圍

### 做
- 人口／戶籍
- 教育
- 就業
- 語言（行有餘力）
- 憲政代表性（已有既有專案，考慮併入或連結）

### 不做
- **土地權屬**：會從「整理公開統計的人」變成「介入爭議的人」，性質不同
- **健康細分**：小樣本反推風險最高
- **原生資料蒐集**：本專案不做調查、不做訪談
- **入口網站**：TIPP 的教訓——做靜態、可重現、有版本的資料集，不做需要長期維運的網站

### 倫理界線

**界線畫在空間解析度，不是畫在主題。**

SEGIS 提供到網格與最小統計區。本專案輸出**止於鄉鎮市區層級**，村里／網格層級不再散布。

參考 CARE 原則與原住民族資料主權主張：族群對自身資料有治理權。本專案處理的是政府已公開發布的加總數字，但仍以最粗的可用解析度為原則。

## 品質分級結果

以**實際回傳內容**判定，不採信 metadata 的格式欄。管線在 `scripts/catalog/`（三階段：取資源網址→打端點→分級），失敗項目全部重試過以區分暫時性故障與真失效。

| 分級 | 筆數 | 佔比 |
|---|---:|---:|
| 真資料 | 600 | 78.6% |
| 二進位（PDF／ZIP／XLS 本體） | 47 | 6.2% |
| 連結殼（欄位是檔案連結） | 33 | 4.3% |
| 網址無效（索引的網址壞掉） | 39 | 5.1% |
| HTML 殼 | 16 | 2.1% |
| 失效 | 18 | 2.4% |
| 空資料 | 3 | 0.4% |
| 無資源 | 7 | 0.9% |

分級只讀探測結果的原始訊號，規則要調整時重跑 `scripts/catalog/grade.py` 即可，**不必再對政府主機發一次請求**。

## 第一張長表

教育部《原住民學生概況統計》的國中小部分（C 系列 6 張表）已攤平成單一長表：

```bash
python -m scripts.moe.fetch              # 取 103–114 共 12 份原始檔（已存在則略過）
python -m scripts.moe.build_long_table   # 攤平，不連網
python -m pytest tests/                  # 23 項不變量測試，約 12 秒
```

產出 `data/processed/moe-c-series-long.csv`，欄位與讀法見 **`docs/schema/moe-c-series.md`**。

選這組先做，是因為它是四大來源中唯一實測證明可跨年度合併的一組，用最低風險的來源把 schema 與 pipeline 定下來，供其餘來源沿用。**讀之前請先看 schema 文件的第一節**——6 張表是同一批學生的 6 種切法，跨 `表號` 加總會重複計算。

建置期做了 12 學年 × 6 表的逐格彙總驗證，並查出 103／105 學年原始檔有 26 處「發布總計 ≠ 明細加總」。長表只存明細，不受影響；逐筆查證結論在 `scripts/moe/known_issues.py`，且被測試反向釘住（上游修好時測試會失敗提醒清理）。

## 下一步

見 `docs/來源盤點.md` 第八節。**去重**——分級時已量出 160 筆共用相同資源網址，明細檔有「與其他資料集共用資源」欄可直接用，但保留哪一筆、名稱如何取捨的規則還沒定。長表 schema 已定，可作為合併規則的判準。

## 已知陷阱

- **格式標示不可信**。標 CSV/JSON 不代表裡面有資料。原民會就業那筆標 JSON/XML/CSV，實際是 24 筆 PDF 連結清單。已量化：宣稱資料格式卻回 HTML 的 49 筆、連結殼 33 筆，約 **11%** 的資料集 metadata 與實際不符。
- **索引壞掉不等於資料死亡**。ODPortal 有 63 個資源網址含字面 `undefined`（臺北市 39 筆資料集全數受影響）。歸因時要把「第三方鏡像的索引壞」與「提供機關的端點死」分開，否則會錯記責任。
- **偵測 PDF 殼不能只看副檔名**。原民會就業那筆的連結是 `DownloadFile.aspx?filno=<guid>`，網址裡沒有 `.pdf`。要看欄位名（`檔案pdf`）與值為連結的比例。
- **三個維度常被混用**：「原住民」（身分別）／「原住民族」（族別）／「原住民地區」（55 鄉鎮）。各機關定義未必一致，口徑要逐一驗證。
- **先實測再寫規格**。任何數字都要是跑出來的，不是推論的。
