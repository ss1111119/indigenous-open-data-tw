# 專案詞彙

本專案的正式用詞。寫文件、寫 commit、對外描述時一律用 canonical 的那個詞。

會需要這份檔案，是因為 2026-08-13 的討論發現「蒐集」一詞被用來指兩件截然不同的事，
而其中一件是專案明確聲明不做的。詞用錯不只是不精確——它會改變別人對這個專案的預期，
在原住民族資料主權的框架下尤其如此。

---

## 編目

**definition**：把已公開的資料集找出來、探測、分級、列成清單。產出是
`catalog/odportal-763-graded.csv`、`catalog/品質分級報告.md`、`docs/來源盤點.md`。
不清洗內容、不統一口徑，只回答「有什麼、哪些能用、哪些壞了」。

**avoid**：蒐集（見下）、彙整、資料庫

**why**：這是專案的第一層，求廣。它的價值有一半在於告訴人「這 39 筆網址是壞的，
別浪費時間」——那本身就是有用的資訊，不必等長表做完。

## 長表

**definition**：把單一來源從頭清到底、攤平成可直接讀進 pandas 的長格式資料。產出在
`data/processed/`。每一份都附 schema 文件說明欄位、口徑與已知陷阱。

**avoid**：資料集（太籠統，`catalog/` 裡列的那些也叫資料集）、清理後的資料

**why**：這是專案的第二層，求深。它證明第一層的品質判斷不是隔著 metadata 猜的——
有人真的把其中一筆做到底。

## 蒐集

**definition**：**僅**指蒐集原生資料，即自行調查、訪談、量測。

**avoid**：不要用「蒐集」指編目。

**why**：這是專案明確不做的事（`README.md`「這是什麼」、`CLAUDE.md`）。
「蒐集原住民族資料」與「重新整理政府已公開的加總統計」在 CARE 原則與原住民族
資料主權的框架下是差很多的兩件事，混用會招來本來不該有的質疑。要講第一層的工作，
用「編目」。

## 口徑

**definition**：一個統計數字的定義範圍——誰被算進去、依據哪種身分認定、涵蓋哪些年度。

**avoid**：定義（過於一般）、標準

**why**：專案最大的未解問題是跨機關口徑不一致。三個常被混用的維度：
「原住民」（身分別）／「原住民族」（族別）／「原住民地區」（55 鄉鎮）。
教育部長表的 `等級別` 用「國中（含進修部）」而非「國中」，就是為了不讓兩種口徑
在同一個標籤下構成假相等。

## 去重

**definition**：把**同一份資料被索引多次**的紀錄合併成一筆。

**avoid**：合併（含意太廣，容易被誤解為把不同機關的資料併在一起）

**why**：2026-08-13 實測確認那 160 筆是同一份資料上架在中央與地方兩個平台
（名稱、資源 `rid` 全同），**不是**各轄區的拼圖碎片。這個區別決定了處理方式：
冗餘該合併，碎片不該合併。把「跨機關資料整合」也叫去重，會讓兩件事混在一起。

---

## 舊用詞何時可以留

- **引用原始檔案的欄名時照原文**。教育部原始檔寫「國中進修部」，長表正規化為
  「國中補校」，但 `docs/來源盤點.md` 描述原始檔時仍用原文，並註明對應關係。
- **git 歷史不追溯修改**。既有 commit message 用了舊詞就留著，不改寫歷史。
