## Context

專案已有兩張長表，pipeline 的作法已在 `flatten-moi-indigenous-population` 定下並驗證。本變更是同一個 API 的第二個資料集，取檔、聚合、村里捨棄、manifest 全部沿用。

**現有約束**：

- 環境已具備 Python 3.13.9、pandas 3.0.0，本變更不新增第三方套件
- `data/raw/` 不入版控，故取檔必須可重跑
- **專案倫理界線：輸出止於鄉鎮市區層級，村里不再散布**
- 專案原則：主張跨某個維度一致時該維度必須全掃、不能抽樣；不變量必須有注入故障測試證明它不是恆真的

## Goals / Non-Goals

**Goals:**

- 產出 15 歲以上原住民教育程度長表，涵蓋 106–114 共 9 年，粒度止於鄉鎮市區
- 教育程度的兩套寫法與身分別欄名的三種變體由對照表吸收，使長表標籤跨期一致
- 在來源沒有彙總欄的情況下，仍在捨棄村里明細前建立可查核的保證
- 113 缺的那 1 列被明確報出並記錄，不被靜默補值或忽略

**Non-Goals:**

- **不保留村里層級明細**（沿用既有決策，且此來源粒度風險更高）
- **不修補 113 缺的 1 列**：報出缺哪個維度組合並記入 manifest，不推估
- **不合併肄業與畢業、不映射教育年數、不做學制分組**
- **不與教育部長表相除**：母體不同（在學學生對 15 歲以上存量）
- **不處理其他 7 個戶政司資料集**
- **不回填 115 之後的期別**

## Decisions

### 以維度交叉完整性取代來源缺少的彙總驗證

`ODRP018` 的七組恆等式建立在來源同時提供總計欄與明細欄。`ODRP026` 沒有任何彙總欄，那些檢查一條都用不上——若照搬既有 spec 的要求，會在「無法驗證」的狀態下捨棄村里明細，等於沒有保證。

決策：以**維度交叉完整性**作為主要驗證——每個村里必須恰有「23 種教育程度 × 2 性別 × 該期身分別數」列，不多不少。列數不符即報出缺漏或多出的維度組合。

這條檢查的鑑別力已在寫程式之前得到證明：純用來源回報的列數做算術，就抓到 113 少 1 列。

**替代方案**：不驗證，直接聚合。已否決——村里明細一旦捨棄即不可逆，沒有保證就不該捨棄。

### 以 `ODRP018` 的村里數做跨資料集對帳

同機關同期別的兩個資料集應涵蓋相同的村里集合。實測相符：111／112 推得 7,748 對上 `ODRP018` 的 11306；114 推得 7,752 對上 11412。

決策：取檔時把該期推得的村里數與 `ODRP018` 同年任一期的村里數比對，不符則報出兩個數字。這是**唯一的跨資料集檢查**，比交叉完整性更強——後者只證明內部自洽，前者證明與另一份獨立資料一致。

⚠️ 此檢查為**警示而非阻斷**：行政區調整可能使兩個資料集的基準月份不同而合理地相差幾個村里。報出差異並記入 manifest，由人判斷。

**替代方案**：設為阻斷性錯誤。已否決——會因正常的行政區調整而誤擋。

### 教育程度以全稱為正規值

23 個值有兩套寫法，7 個期別用全稱、2 個用縮寫。

決策：正規值取**全稱**（`小學畢業` 而非 `小畢`）。理由：全稱無歧義，而縮寫有實際的誤讀風險——`二畢` 看似二專實為「二、三專」、`後二畢` 看似「後二年畢業」實為「五專畢業」。對照表寫成資料，未列在表中的值視為阻斷性錯誤。

**替代方案**：取縮寫以節省檔案大小。已否決——為了壓縮而選一個會被誤讀的標籤，代價與收益不成比例。

### 沿用既有的取檔基礎，一般化驗證的接口

取檔的分頁、重試、未發布判定、聚合到鄉鎮市區、村里捨棄、manifest 都與 `ODRP018` 相同，已在既有 capability 中規範。

決策：把 `moi-population-ingest` 的驗證要求一般化為「來源有彙總欄時驗恆等式，沒有時驗維度交叉完整性」，兩個資料集共用同一個 capability，而非複製一份。

**替代方案**：新增獨立的 ingest capability。已否決——分頁、未發布判定、村里捨棄的規範會被複製兩份，日後修正要改兩處。

### 113 缺的列報出但不補

實測 113 比完整交叉積少 1 列。原因未知，可能是上游漏發布某個村里的某個組合。

決策：取檔時找出缺哪一個維度組合，報出並記入 manifest，**該期仍照實產出**（少一列）。不以 0 補值，也不因此中止該期。

理由：補 0 會製造來源沒有的數字；中止該期會為了一列而丟掉 71 萬列。長表因此在該組合上沒有列——與「平埔在 11411 之前不產列」同一個原則：**來源沒說的事，長表不說**。

**替代方案**：以 0 補齊。已否決——見上。**替代方案**：中止該期。已否決——比例失當。

## Implementation Contract

**行為**：取檔指令逐期取得 `ODRP026` 並寫出鄉鎮市區層級結果與 manifest 至 `data/raw/moi-education/`；建置指令讀該結果產生 `data/processed/moi-indigenous-education-long.csv.gz`，不發出任何網路請求。重跑建置產生位元組相同的輸出。

**資料形狀**：長表欄位為 `統計年`、`縣市`、`鄉鎮市區`、`身分別`、`教育程度`、`性別`、`人數`。

- `統計年` 為民國年的整數（例如 114）
- `縣市` 與 `鄉鎮市區` 為字串，均必填；行政區名一律用「臺」
- `身分別` 為必填字串，取值為平地原住民、山地原住民、平埔原住民之一
- `教育程度` 為必填字串，取 23 個全稱之一
- `性別` 為必填字串，取值為男或女
- `人數` 為非負整數，永不為空
- 輸出為 gzip 壓縮的 CSV，gzip 標頭的 mtime 固定為 0

**指令介面**：取檔與建置為可分別執行的兩個步驟。取檔接受期別範圍參數，已有完整紀錄的期別不重複取得。建置只讀本機檔案。

**失敗模式**：

- 某期別的列數不是維度交叉積的整數倍 → 報出缺漏或多出的維度組合、該期仍產出（阻斷性例外，見下）
- 教育程度出現對照表未列的值 → 報出期別與該值並中止（阻斷性）
- 身分別欄名無法判定 → 報出該期實際欄名並中止（阻斷性）
- 實際取得列數與來源回報的總列數不符 → 報出兩個數字與期別並中止（阻斷性）
- 村里數與 `ODRP018` 不符 → 報出兩個數字並記入 manifest，不中止（警示）
- 建置時 manifest 與聚合結果的期別集合不一致 → 報出差集並中止（阻斷性）

**驗收標準**：

- 長表涵蓋 106–114 共 9 個統計年
- 8 個期別的維度交叉完整；113 恰缺 1 個組合，且 manifest 記載缺的是哪一個
- 114 的身分別有 3 種、其餘期別 2 種
- `教育程度` 取值恰為 23 個全稱，不含任何縮寫
- 長表不存在 `人數` 為空的列，且 `人數` 皆為非負整數
- 連續兩次建置產生位元組相同的輸出
- 測試對「維度交叉完整」與「教育程度正規化」兩項注入故障後會失敗

**範圍界線**：

- 在範圍內：`ODRP026` 的取檔、聚合、驗證、攤平、對照表、測試、schema 文件、既有 ingest capability 的驗證要求一般化、README 與盤點文件更新
- 在範圍外：村里層級輸出、其他 ODRP 資料集、與教育部長表的交叉使用、113 缺列的補值、教育程度的任何再分組

## Risks / Trade-offs

- **取檔規模是 `ODRP018` 的八九倍**：9 期 × 356–535 頁 ≈ 3,600 個請求 → 沿用既有的重試與可重跑機制，中斷後續跑會跳過已完成期別；並在取檔輸出逐期進度，使長時間執行看得見進展

- **教育程度對照表若對錯，錯法是靜默的**：`二畢` 與 `後二畢` 兩個縮寫的字面意思與實際涵蓋範圍不同 → 對照表寫成資料並附註這兩個陷阱；未列在表中的值一律報錯而非略過；測試釘住「輸出的 23 個值恰為全稱集合」

- **113 缺的 1 列原因未知**：可能是上游漏發布，也可能是我們的交叉積假設在該期不成立 → 取檔時報出缺的是哪一個維度組合並記入 manifest，使後續能判斷是隨機漏失還是系統性缺口

- **跨資料集村里數對帳可能誤報**：`ODRP026` 是年報、`ODRP018` 是月報，基準月份未必相同，行政區調整會造成合理差異 → 設為警示而非阻斷，並在 manifest 記錄比對用的是 `ODRP018` 哪一期

- **來源沒有彙總欄，驗證強度低於 `ODRP018`**：那邊有七組恆等式逐列比對，這邊只有列數與村里數 → 誠實記錄此差異；交叉完整性雖然較弱，但已證明能抓到真實異常（113），且跨資料集對帳提供了 `ODRP018` 沒有的獨立驗證
