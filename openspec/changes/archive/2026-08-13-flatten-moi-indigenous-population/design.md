## Context

專案已有一張長表（教育部國中小 C 系列），schema 與 pipeline 的作法已在該變更中定下並驗證。本變更是第二個來源，沿用同一套原則：註冊表描述結構、只存明細、彙總用於驗證後捨棄、不變量測試釘跨檔案約束。

來源是內政部戶政司開放資料的 `ODRP018`（現住原住民人口按性別、身分、原住民族別分），全國、月報、免登入、URL 規律。

**現有約束**：

- 環境已具備 Python 3.13.9、pandas 3.0.0，本變更不新增第三方套件
- `data/raw/` 不入版控，故取檔必須可重跑
- **專案倫理界線：輸出止於鄉鎮市區層級，村里不再散布**
- 專案原則：安全網釘跨檔案不變量，不釘單一數字；提案與設計裡的數字必須是實測而非推論

**已實測確認的結構**（2026-08-13）：

- 每期 4 頁、每頁 2,000 列，分頁參數為查詢字串的 page
- 村里列數逐期微變：10701 為 7,823、11306 為 7,748、11412 為 7,752、11507 為 7,781
- 11507 聚合後為 368 個鄉鎮市區
- 單頁約 7 MB，全部期別的村里原始資料約 2.9 GB

## Goals / Non-Goals

**Goals:**

- 產出全國原住民人口長表，涵蓋可取得的全部期別，粒度止於鄉鎮市區
- 跨期的欄名與族名改版由註冊表吸收，使長表的族別標籤跨期一致
- 平埔列只在來源真的帶該欄位的期別出現
- 取檔留下可驗證的紀錄，使捨棄村里明細後仍能查核當時驗過什麼
- 以不變量測試釘住跨期與跨維度的約束

**Non-Goals:**

- **不保留村里層級明細**（見下方決策與風險）
- **不處理 `ODRP009`**：只有一期且已被取代
- **不處理其他 8 個戶政司原住民主題資料集**：待 schema 驗證可用後以獨立變更擴充
- **不做跨機關口徑統一**：本長表與教育部長表能否相除需另行查證母體定義
- **不推導新指標**：不算比率、成長率、佔比
- **不回填 11508 之後的期別**：平埔轉為非零時以獨立變更處理

## Decisions

### 於取檔階段聚合到鄉鎮市區，捨棄村里明細

倫理界線是專案層級的承諾，且有實測依據：村里層級 7,524 個非零列中 1,897 列（25%）少於 10 人，「村里 × 單一族別 × 性別」有 32,936 格的值為 1 或 2；聚合到鄉鎮市區後少於 10 人的只剩 2 列（1%）。

保留村里明細的唯一功能是日後輸出更細的粒度，而那是專案承諾永不做的事。往更粗的方向不受影響——鄉鎮市區可再聚合為縣市，無須重抓。資料最小化本身也是 CARE 原則的一部分，而專案在 README 引用了它。

決策：取檔步驟連網取得村里資料、於記憶體內完成驗證與聚合，只把鄉鎮市區層級的結果落地至 `data/raw/moi/`。建置步驟讀該結果，不連網。

⚠️ **此決策不可逆，且與 C 系列的方向相反。** C 系列捨棄的是彙總值，那可以從明細重算；本變更捨棄的是明細，**無法從聚合重算**。要恢復村里粒度只能重新發出全部請求。這是刻意選擇的資訊損失，因為被捨棄的正是承諾不散布的部分。

**替代方案**：把 2.9 GB 村里原始檔留在 `data/raw/`。已否決——為保留一個承諾不使用的能力而長期持有最敏感的粒度，與專案的倫理立場不一致。

### 取檔留下 manifest，使捨棄後仍可查核

明細捨棄後，「當時到底驗過什麼」無法事後重現。若不留紀錄，聚合結果就成了無法追溯的斷言。

決策：每期在 `data/raw/moi/` 寫一筆取檔紀錄，內容為期別、來源回報的總列數、實際取得的列數、頁數、聚合後的鄉鎮市區數、七組恆等式的檢查結果、欄名版本（三種命名方案之一）、取檔時間。

**替代方案**：只存聚合結果。已否決——聚合值與其驗證狀態脫鉤，日後無從判斷某期是否曾通過檢查。

### 以註冊表描述跨期欄名與族名改版

來源用過三種命名方案，差異不只前綴：中文方案的「總計」在頂層與身分別用不同的詞（總計對合計）、族別欄多一個尾綴、性別與維度欄名皆為中文。硬編碼任一方案都會在其他方案靜默取到空值或漏族。

決策：註冊表以**中文族名**為正規值，並把每種命名方案寫成一個資料條目（辨識欄位、維度欄對映、頂層與身分別的片段、總計用詞、性別寫法、尾綴、族名是否為中文）。取檔時先偵測該期屬哪個方案，再依方案組出欄名。新增第四種方案只需多一個條目，不改程式。出現註冊表未描述的欄位視為阻斷性錯誤，因為那可能是新的改版。

這與 C 系列把「國中進修部」正規化為「國中補校」是同一手法。

**替代方案**：分版本寫兩套解析邏輯。已否決——**而且這個否決在本變更中就已應驗**：實作時發現有第三種方案（11308 的中文欄名），若當初寫死兩套，此時就要寫第三套並複製一遍驗證邏輯。

### 平埔列只在來源帶該欄位的期別產出

11410 及之前的來源**沒有**平埔欄位；11411 起有欄位但值為 0。兩者語意不同：前者是「來源未提供此維度」，後者是「來源說是 0」。

一律填 0 會讓長表出現「10701 的平埔原住民為 0 人」這種來源沒說過的陳述。

決策：`身分別` 取值為平埔的列，只在該期別的來源確實帶平埔欄位時產出。11411 至 11507 產出且人數為 0；11410 及之前不產列。11508 之後值轉為非零時，schema 與程式都無須改動。

這直接沿用 C 系列的設計決策「以註冊表宣告的合法維度組合限制產列範圍」——當時處理的是國中沒有四年級。

**替代方案**：全期填 0。已否決——把「未提供」與「為零」壓成同一個值，且該資訊無法從長表復原。

### 長表只存明細，彙總值用於驗證後捨棄

來源同時提供總計欄與族別明細欄、以及身分別小計。實測七組恆等式零容差成立。

決策：長表只保留「族別 × 性別 × 身分別」的最細組合；總計欄與身分別小計在取檔時用於驗證，通過後捨棄。任一期任一列驗證不通過即為阻斷性錯誤。

**替代方案**：保留總計欄。已否決——未過濾的彙總會使 `groupby().sum()` 得到數倍數字，與 C 系列同一個坑。

### 不變量測試釘跨期與跨維度約束

要釘的約束：每個「期別 × 鄉鎮市區 × 身分別」群恰有該身分別的族別數乘以性別數之列（維度交叉完整）；`身分別` 為平埔的列只出現在 11411 及之後；族別標籤跨期一致（不因改版而分裂成兩組）；每期的鄉鎮市區數與 manifest 相符；長表不含彙總列。

⚠️ **原先寫的是「每期的族別加總等於該期的身分別加總」，2026-08-13 實作時發現該式恆真**——兩者都是把同一批列相加，與資料正確性無關，注入故障也不會失敗，違反專案「避免測試恆真」的驗收要求。已改為維度交叉完整性：它抓得到漏列、重列，以及某族因欄名改版而對映失敗（那正是本變更最大的結構風險）。

## Implementation Contract

**行為**：取檔指令逐期取得資料並寫出鄉鎮市區層級結果與 manifest 至 `data/raw/moi/`；建置指令讀該結果產生 `data/processed/moi-indigenous-population-long.csv.gz`，不發出任何網路請求。重跑建置產生位元組相同的輸出。

**資料形狀**：長表欄位為 `期別`、`縣市`、`鄉鎮市區`、`身分別`、`族別`、`性別`、`人數`。

- `期別` 為民國年月的整數（例如 11507）
- `縣市` 與 `鄉鎮市區` 為字串，均必填；行政區名一律用「臺」
- `身分別` 為必填字串，取值為平地原住民、山地原住民、平埔原住民之一
- `族別` 為必填字串，取中文族名或「尚未申報」
- `性別` 為必填字串，取值為男或女
- `人數` 為非負整數，永不為空
- 輸出編碼為 UTF-8 帶 BOM，換行為 LF
- **輸出為 gzip 壓縮的 CSV（`.csv.gz`）**，並固定 gzip 標頭的 mtime 為 0

⚠️ **原先規劃為純 CSV，2026-08-13 實作後改為 gzip。** 實測未壓縮為 **151.6 MB**，超過 GitHub 單檔 **100 MB 的硬上限**（50 MB 即警告），純 CSV 根本進不了儲存庫。壓縮後 **8.9 MB**，且 `pd.read_csv` 能直接讀 `.csv.gz`，「可直接讀進 pandas」的定位不受影響。失去的是 Excel 直接開啟——但 151 MB 的 CSV 本來也不在 Excel 的舒適範圍。

⚠️ **gzip 標頭的 mtime 必須固定為 0。** 預設會嵌入建置時間，那會使每次輸出的位元組都不同，靜默破壞「重跑產生位元組相同的輸出」。實測固定後，間隔 1.2 秒重建的雜湊值相同。

⚠️ 這使兩張長表的存放格式不一致（C 系列為純 CSV，20.2 MB 未觸及限制）。統一格式需另開變更，本變更不處理。

**替代方案**：按年度切成 9 檔（最大 18.1 MB）。已否決——違背「單一長表」的定位，使用者得自行 concat 9 個檔。**Parquet**（2.2 MB）已否決——需要 `pyarrow`，違反本變更「不新增第三方套件」的約束。**只留非零列**（55.6 MB）已否決——仍超警告線，且 62.9% 的列為 0，刪掉會讓「組合存在但為 0」與「組合不存在」再度混淆，那正是本變更花力氣區分的東西。

**指令介面**：取檔與建置為可分別執行的兩個步驟。取檔接受期別範圍參數，已有完整紀錄的期別不重複取得。建置只讀本機檔案。

**失敗模式**（皆為阻斷性錯誤，不設靜默降級路徑）：

- 某期別回「查無資料」而該期在請求範圍內 → 報出期別與代碼，並區分「尚未發布」與「請求失敗」
- 實際取得列數與來源回報的總列數不符 → 報出兩個數字與期別
- 七組恆等式任一不符 → 報出期別、村里代碼、不符的等式與差值
- 出現註冊表未描述的欄位 → 報出期別與欄名，因為那可能是新的改版
- 某期的欄名版本無法判定 → 報出該期實際的欄位前綴
- 建置時 manifest 與聚合結果的期別集合不一致 → 報出差集

**驗收標準**：

- 長表的期別集合與 manifest 記錄的期別集合完全相同
- 11507 的長表資料聚合後為 368 個鄉鎮市區，全國總人數 638,466
- 11507 的平地為 298,327、山地為 340,139
- `身分別` 為平埔原住民的列，其期別最小值為 11411
- 長表不存在 `人數` 為空的列，且 `人數` 皆為非負整數
- 族別標籤集合跨期一致，不含羅馬字
- 連續兩次建置產生相同輸出
- 測試對「維度交叉完整」與「平埔列的期別下界」兩項注入故障後會失敗

**範圍界線**：

- 在範圍內：`ODRP018` 的取檔、聚合、驗證、攤平、註冊表、測試、schema 文件、README 與盤點文件更新
- 在範圍外：村里層級輸出、`ODRP009` 與其他戶政司資料集、跨機關口徑比對、衍生指標、11508 之後的期別

## Risks / Trade-offs

- **捨棄村里明細不可逆**：恢復需重新發出全部請求（約 412 個）→ 取檔時先完成全部驗證再聚合，並把驗證結果寫入 manifest，使捨棄後仍可查核當時驗過什麼

- ~~**期別連續性未經逐期驗證**~~：**已解除。** 2026-08-13 逐期取完，10701–11507 的 103 個期別全部存在且成功取得，0 期失敗、0 期未發布

- ~~**算術驗證只做過一期**~~：**已解除。** 七組恆等式已對全部 103 期逐列執行，零容差通過；每期的檢查次數記在 manifest

- **上游可能再次改版**：族名羅馬字已改過一次，可能再改 → 註冊表以中文族名為正規值並列出別名，未描述的欄位一律報錯而非靜默略過

- ~~**平埔欄位的下界只在抽測期別上確認**~~：**已解除，且抽測結論是錯的。** 原判定下界為 11412，逐期取完後確定是 **11411**——11411 已是 162 欄並帶平埔欄位（值為 0）。此錯誤由「欄數與註冊表宣告不符」的阻斷性錯誤擋下，未產出漏一期平埔的長表。取檔仍逐期比對平埔欄位存在與否是否與宣告的下界一致，不一致即報錯

- **平埔轉為非零時的解讀風險**：11508 起數字上升可能被誤讀為原住民人口成長，實際是新類別納入 → schema 文件明寫平埔列的期別下界與其法源背景，並在長表以獨立的 `身分別` 值呈現而非併入總計
