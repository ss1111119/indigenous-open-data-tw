2026-08-11 於 [[moe-indigenous-stats]] 確立並實測，使用者核准。

**Why:** 資料專案的錯誤型態是**靜默的口徑錯誤**，不是例外。那天一天內至少四次
靠人工比對才發現問題——某份資料的鄉鎮加總與縣市檔逐縣市完全相符（內部一致），
對外卻全錯（某縣市 15 歲以上人口比該縣市原住民總人口還多）；占比兩次四捨五入；
規格範例填了未實算的數字。**這些都不會讓任何程式報錯。**

## How to apply

1. **釘跨檔案的關係，不要釘單一數字的自我複述。**
   「A 檔的合計 = B 檔某列」這種約束，兩邊由不同腳本從不同來源產生，
   一起錯的機率遠低於各自錯。只斷言「A 檔某數字 = 常數」則只是把值抄兩遍。

2. **期望值寫死，並接受資料更新時會紅。** 若改成「從另一個檔案算出來再比對」，
   兩邊一起錯時測試仍會通過。紅燈是刻意的——資料推進本來就該有人看過數字再更新。
   失敗訊息要寫「請先確認數字合理再更新常數，不要為了通過而改測試」。

3. **測試只讀已入版控的產物，不讀未入版控的原始資料。** 依賴後者就會變成
   「clone 之後跑不起來」，那種測試沒有人會跑。目標是幾秒內、免連網。

4. **⚠️ 不要把斷言建立在「敘述會提到某個東西」上。**
   曾寫了「檢查開場白宣稱的區塊數是否與實際相符」，看似合理——但把開場白改寫成
   不含數字的句子之後，那條斷言就變成**空的**，新增區塊也不會紅。
   **正解是釘住結構本身**（區塊清單），讓改動結構這件事直接觸發失敗，
   再由失敗訊息要求作者回頭確認敘述。

5. **注入故障驗證測試真的會紅。** 寫完就跑一次不夠——上面第 4 點正是「寫完跑過、
   全綠」但實際抓不到東西。每種它該抓的故障都手動製造一次。
